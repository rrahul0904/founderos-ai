# Falbor-inspired reverse-engineering notes

FounderOS takes inspiration from a general product insight observed in Falbor: product context is lost when founders move through separate research, planning, coding, deployment and monitoring tools.

We intentionally do **not** clone the product. FounderOS differentiates around:

1. evidence intelligence and source provenance;
2. explicit decision memory;
3. contextual retrieval for specialized agents;
4. guarded, auditable execution;
5. a closed learning loop after deployment.

The desired lifecycle is:

```text
Idea → Evidence → Decision → Spec → Architecture → Build → Deploy → Learn → Next decision
```

The long-term moat is the longitudinal product graph: what the team believed, what evidence changed its mind, what it built, what users did, and why the next iteration was chosen.
